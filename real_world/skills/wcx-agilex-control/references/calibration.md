# 双臂与多相机标定：复用流程，独立实体参数

用于相机外参、腕部手眼、相机到双臂基座关系的采集和验证。先选服务器及实体绑定，再沿用已有 `observe`、`move_left/right/both`；本流程不增加控制器，不重放另一场景的采样关节角。检测与求解实现集中在 `src/agilex_control/calibration_board.py` 和 `calibration_hand_eye.py`。

## 先确定要求解的关系

把变换写成 `T_目标_源`，左乘列向量，平移单位统一为毫米。以下方法适用于腕相机刚性安装在末端、机械臂基座固定、同一块标定板在采样期间固定的情况；一台或多台腕相机分别求解，不要求两臂同时采样。求解器只接收位姿矩阵，不依赖 Piper 或六关节结构；其他机器人须用自身已核验 FK 和已有动作接口提供末端位姿。

- `G_i = T_base_end(i)`：停稳后实测关节经本机 FK 得到，不能使用命令目标或复制另一臂模型。
- `C_i = T_camera_board(i)`：当前图像、该帧内参和实体板尺寸的 PnP 结果。
- `X = T_end_camera`：需要求出的腕相机安装变换。
- 板固定时 `G_i X C_i = B = T_base_board`。不同姿态的该乘积应一致。
- 固定顶部相机同时看到板，记 `P_i = T_top_board(i)`，则 `T_base_top = B P_i^-1`。
- 两臂观察同一固定板时 `T_leftbase_rightbase = B_left B_right^-1`。两臂必须使用同一物理尺寸与板坐标定义。

这条链可一次关联左右腕相机、固定相机和两个基座。无腕相机、板固定在夹爪上或相机不是刚性安装时，先选对应的标定模型；不要硬套“桌面板固定”的求解器。手眼标定不等于指尖 TCP、机器人几何、相机内参或深度标定。

## 尺寸、身份与采集准备

1. 按现场档案取当前 RGBD、完整反馈和控制权状态；不重复启动已有相机服务。确认相机序列号、实际分辨率、畸变模型、RGB/深度对齐与每帧内参。仅通过一次单臂的小幅已授权移动和图像变化就能验证腕相机绑定时，不扩大设备排查。
2. 保存本次板定义：字典、格子数、marker IDs、格长、marker 长、border bits、legacy pattern、单位和实测来源。缩印可以按实测尺寸使用；“100 mm 标尺约 93 mm”只能支持暂估 0.93。横纵等比性、纸张平整度和精确尺寸未知时保持标记，不能称为经过计量验证的尺寸，也不改原始打印模板。
3. 优先复用当前流的有效内参。RealSense 的 `inverse_brown_conrady` 不能直接当作 OpenCV 普通 Brown 畸变：共享检测器用 RealSense 解投影归一化射线，再做 PnP。`none`、`brown_conrady` 使用普通 OpenCV 路径，不依赖 RealSense；不认识的畸变模型明确失败。
4. 根据新图像和当前位置选择看板姿态，先 dry run。低速在可观察的空旷区域采样；先小范围转向，再用新图像调整覆盖。move 没有固定准备姿态；使能、控制模式和轻微越界恢复沿用本站现成流程。

## 采样与质量控制

一般从每腕约 10–16 个训练姿态及 3–4 个独立留出姿态开始，是否补采由覆盖和残差决定。预先确定留出集合，不用它拟合或挑选算法。绕两个非平行轴产生充分转动，例如各约 20–40° 跨度，再加入多个方向几厘米的平移；实际范围由当前视野、机构和障碍物决定。只绕一个轴退化；只保持末端 XYZ 不变转动通常不能可靠估计打印尺度。

每个姿态调用原 move，停稳后调用原 observe，保存图像、深度、逐帧参数、实际关节/FK 和时间戳。相机与关节没有硬同步时，只使用静止采样，不能把运动中的异步数据当同步测量。保留请求、实际反馈和数据路径；发送成功不等于位姿达到。

- 原图确认板在视野内、无严重遮挡，覆盖多个非共线角点。部分板可用，但不能把少数拥挤角点当成完整覆盖。
- 检测器保存角点、ID、正深度 PnP 双解、重投影误差与深度平面质检；`eligible` 仅代表图像样本可进入候选集，不是标定通过。
- 用固定相机同 ID 角点位移监测板是否移动，并复核其 PnP 稳定性。板被碰动则分段或重采该段；不能混成一个固定板数据集。没有固定观察源时，以其他现场证据验证板固定。
- 实机故障、数据过期、板出视野或异常位移后先停止追加采样、保存完整状态和图像，再决定如何恢复。不得通过放宽硬件限位或虚构反馈继续。
- 对齐深度的平面偏差是独立质检项，不能仅用某台相机的深度差去改纸张尺度或另一台相机参数。

## 已有离线入口

从项目根设置 `PYTHONPATH=src`，选择具有所需依赖的现有 Python。检测需 OpenCV/NumPy，以及 `aruco.CharucoDetector`、含IDs参数的 `CharucoBoard`、`matchImagePoints`、`solvePnPGeneric/IPPE`、`solvePnPRefineLM` 等 API；inverse Brown 另需 pyrealsense2。已验证 OpenCV 4.11/4.13，手眼求解还需 SciPy 和实际可调用的 `cv2.calibrateHandEye`；仅存在 `CALIB_HAND_EYE_*` 常量不代表函数可用。检测和求解可以分别运行于两个现有环境，不必为统一环境安装依赖。

```bash
python -m agilex_control.calibration_board \
  --observation /absolute/observation \
  --board /absolute/physical-board.json \
  --output /absolute/new-detection.json

python -m agilex_control.calibration_hand_eye \
  --input /absolute/one-arm-samples.json \
  --output /absolute/new-solution.json
```

观察目录沿用 `observe` 的各相机 `rgb.jpg`、可选 `depth.npy`、`metadata.json`。元数据含 `serial,width,height,fx,fy,cx,cy,model,coeffs`；有深度时提供 `depth_scale_m`。板 JSON 沿用上述参数以及 `squares_x,squares_y,square_length_mm,marker_length_mm,dictionary,marker_ids`。

一个腕相机/一臂一份求解输入，顶相机项可省：

```json
{
  "schema_version": 1,
  "site_id": "现场身份",
  "arm": "实体臂身份",
  "camera_serial": "实际相机序列号",
  "board": {"square_length_mm": 27.9, "physical_dimensions_verified": false},
  "samples": [{
    "id": "pose-01", "split": "train",
    "T_base_link6": "实测末端到基座的4×4数值矩阵",
    "T_camera_board": "板到腕相机的4×4数值矩阵",
    "top_T_camera_board": "板到固定相机的4×4数值矩阵"
  }]
}
```

上例的矩阵说明字符串须替换为真实数值数组；27.9 只是缩印案例，不是默认格长。`T_base_link6` 是现有接口字段名，其他机器人可传其固定末端参考帧，但必须在元数据记录真实帧名并始终一致。样本 `split` 为 `train` 或 `holdout`；保存原观测路径和实测时间，便于复算。

求解输入 `board` 的尺寸字段必须与生成 PnP 的物理尺寸假设一致。若记录 `scale_bar_mm`，它表示同一尺度下的实体暂估长度（例如 93），原打印文件的名义 100 应另存 `nominal_scale_bar_mm`；不能直接复制名义值混用。

只移动固定相机、已有腕手眼仍有效时，向同一求解输入增加 `known_T_link6_camera` 数值矩阵及来源/实体身份。该路径直接复用 X，输出 `known_hand_eye` 中的板/固定相机变换，不重新拟合手眼，也不要求双轴旋转；保留至少 3 个训练观测与独立留出，重复静止采图可降低随机噪声。它沿用输入 PnP 的尺寸假设，不估尺度；尺寸未知仍是尺度相关候选，不能因多拍几张就称为精确结果。

## 求解、验证和发布

共享求解器比较 Park/Tsai/Horaud，分别报告固定板尺度的结果和可选统一尺度估计。后者用机器人平移估计板尺寸修正，并报告秩、条件数、旋转激励及条件标准误差；它是依赖机器人模型的推断，不能证明纸张横纵等比或修复内参、模型、安装、板移动错误。两臂对同一板的尺度估计应交叉比较，不把两套相互矛盾的尺度直接拼成一个双臂坐标系。

只用训练样本拟合 `X` 和固定板均值；留出样本报告板在基座下及固定相机在基座下的平移/转角残差。还要检查：不同算法是否一致、相机相对末端的安装结果是否合理、固定相机的板观测是否稳定，以及是否满足当前任务所需精度。单帧低重投影误差、低训练残差或两算法相同均不足以证明绝对精度。

结果始终先是候选，求解器不会自动写控制配置（`accepted_for_control:false`）。把身份、坐标方向、单位、帧模式、尺寸测量不确定性、训练/留出清单、残差、有效范围和来源写进本站新版本标定包，再根据任务需要选择是否使用。精确接触/插入所需的 TCP 和物理点验证应另做，不能用手眼内部一致性代替。旧标定和其他站点文件保留。

## 场景变化后的复用边界

| 发生的变化 | 需要重做什么 |
|---|---|
| 物体移动、桌面物品变化，机器人与相机安装未动 | 重新观察和定位目标、规划避障；手眼外参通常可保留，先快速验证 |
| 采样过程中板被移动 | 分段/重采；固定板方程不允许混合位置 |
| 标定完成后板移走 | 外参不因此失效；保存验证证据，后续目标重新定位 |
| 腕相机、支架或末端连接被拆装 | 重做该腕手眼及依赖它的基座关系 |
| 固定相机移动，腕安装和基座未变 | 用有效腕手眼重求固定相机到基座；不必无条件重做两腕手眼 |
| 基座移动、机器人几何/零点模型改变 | 重核 FK 和受影响的基座外参；腕刚性安装变换可候选保留但需验证 |
| 分辨率、裁切、焦距或畸变参数变化 | 使用新模式的内参重新求图像姿态并验证；不能复制旧像素参数 |
| 更换夹爪/工具/指尖 | 核验安装碰撞与 TCP；腕相机刚性安装关系是否变化单独判断 |
| 更换机器人或相机类型 | 复用矩阵算法/数据契约；核验并适配自身 FK、采集和动作后端，不复制实体参数 |

`.1` 的实际板尺寸估计、相机绑定、采样和验证结果见 [本站记录](site-houzhi1.md)。这份流程的可复用性来自明确不变量与验证步骤，不意味着任意硬件与任意布置都能无条件直接运行。
