# 新增服务器、机械臂与驱动

当前入口保留版本化的服务器档案和独立运行配置；技能、模型决策流程和现有 primitive 名称不因新增现场而改变。

开始适配前读 [复用边界及现有后端假设](portability.md)。机械臂、相机、工具/负载和标定均有实体身份，不能从旧站点继承或覆盖参数；如果两臂几何/限位不同，现有共享FK配置也需先按臂扩展。

## 新增同类型服务器

在 [servers.json](../../../config/servers.json) 的 `sites` 字典增加一个唯一 ID，填写：

| 字段 | 契约 |
|---|---|
| `ssh` | `host`、`user`、`port`；不包含密码或认证文件 |
| `expected_hostname` | 实际登录确认的主机身份 |
| `reference` | 相对项目根目录的现场文档路径 |
| `native_project` | 已发现的远端项目绝对路径 |
| `native_python` | 原生驱动需要时填写其解释器路径 |
| `robot_models` | 按逻辑臂记录已确认型号，未知则明确待确认；系列名/固件版本不能代替型号 |
| `primitive_deployment` | 共享 primitive 已部署时填写 `project`、`python`、`config`、`runtime_dir`；否则为 `null` |
| `validation` | `date`、`level`、`detail`，清楚标记连接检查、离线测试和实机验证的范围 |
| `calibration` | 本站标定文件及适用范围；尚未标定则为 `null` |

`schema_version: 1` 表示上述档案格式。选择器按字典内容工作，没有服务器数量上限；接受唯一的 ID 或完整 IP，不接受歧义目标。新增档案和一份现场说明即可被选择器发现，无需修改其源码。若同一 IP 有多个设备档案，用各自 ID 选择，不能由 IP 猜选。

可以先为 `get_state` 建立只有已核验 CAN 接口的读取配置，物理角色未确认时使用总线标签；相机、FK、关节和夹爪边界缺项保持缺失。部分部署时，在 `primitive_deployment.supported_primitives` 和本站工具清单中明确范围。逐项核验新现场 CAN/主从拓扑、相机 SDK 身份、FK、边界和依赖后，再建立对应观察/运动配置；已有 `.56` 配置路径和服务兼容保留。不要先复制旧标定或填猜测值让配置看起来完整。

## 保留控制接口

通用契约以 [tools.json](../../../config/tools.json) 为准：`get_state`、`observe`、`move_left`、`move_right`、`move_both`、`set_gripper_left`、`set_gripper_right`、`stop`。`get_state` 是现有实现的状态读取入口，现已补入工具清单；站点扩展不修改既有名称、单位、参数或反馈结构，显式 `--config` 调用继续工作。

- 同系列、同协议机械臂：完成硬件和协议核验后复用共享实现，新增本站配置。
- 型号几何不同但六轴 modified-DH 契约相同：使用独立 `mdh_mm_rad` 配置并记录来源/实测；不与旧 `fk_file` 同时设置，不按 IP 在运动循环加分支。`.38` 的 Piper X 是已验证实例；型号与固件控制语义仍分别核验。
- 不同型号/协议：在 `src/agilex_control` 的实现边界增加驱动适配，并验证读取、规划、停止和动作语义；按上述契约提供能支持的操作，明确报告不支持的能力。当前没有声称已实现其他品牌适配器。
- 同一服务器增加额外机械臂：保持 `move_left/right` 对现有设备的明确含义。新角色需要显式入口或适配，不把第三只臂偷偷重绑到已有名字，不把“接口可扩展”当成已实现任意臂数控制。
- 硬件差异留在配置/驱动层；不在通用运动循环、抓取策略中按 IP 添加分支。跨服务器协调由上层分别调度，不能把 `move_both` 当跨主机同步接口。

每次扩展验证唯一选站、域用户名传递、配置/标定隔离和失败不换机；驱动扩展另测协议与运动。现有 [站点选择回归](../../../tests/test_sites.py) 包含不改选择器源码就能加入第三个现场的离线案例，不访问测试 IP 或实体设备。
