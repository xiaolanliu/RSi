# 复用边界：物理实体、接口语义与当前状态

同一条命令的实际结果取决于设备、驱动语义、安装/工具、当前状态和环境。IP 可达、型号相同或 JSON 字段相同，都不能证明这几项相同。因此先区分“算法”“驱动假设”“实体参数”“实时状态”，再决定能否复用。

## 可共用与必须独立的内容

| 内容 | 复用条件与独立要求 |
|---|---|
| 工作流、数学与数据格式 | 共用观察—规划—执行—验证流程、矩阵运算、轨迹插值及结果结构；维度、单位、坐标约定和适用条件必须明确。数学可运行不证明轨迹适合新机器。 |
| 驱动与通信语义 | CAN帧ID/节点地址/偏移、ROS topic、主从转发、模式、使能位、命令缓存、故障位和停止行为依赖设备与固件；核验等价后才能共用对应驱动。SDK同名或版本相近不能代替核验。 |
| 机械臂几何 | 自由度、关节顺序/方向、编码器零点、DH/URDF、安装方向、基座之间的变换及FK模型属于具体机械臂/安装。读取现有零点和配置不等于获准重设。 |
| 工具与动力学 | 夹爪类型、开度零点/范围、TCP偏移、附加工具、负载质量/重心、夹持力标定、速度/加速度能力分别核验。旧任务的1.2 N·m不是新夹具/物体的通用夹持参数，电机力矩也不是指尖接触力。 |
| 约束和保护 | 关节限位、碰撞保护、控制模式、驱动/固件限制、工作空间和急停链路属于本站；不覆盖为另一台数值，也不为通过规划自动放宽。历史移除的任意软件阈值不意味着移除设备真实保护。 |
| 相机与标定 | 每台相机分别保存SDK身份、实际分辨率/帧率、畸变模型、内参、深度比例、RGB/深度对齐关系、曝光等采集设置、相机到基座/末端的外参。相机型号/角色相同不代表参数相同；同一相机重新安装或更换分辨率也需复核适用性。 |
| 连接、拓扑和软件环境 | IP/SSH账号、主机身份、CAN物理端口、实体臂角色、主从接线、相机USB带宽、Python/SDK/ROS版本和项目路径按站点保存；名称相同不证明绑定了同一实体。 |
| 场景与任务目标 | 桌面/桶/花瓶/物体坐标、障碍物、线缆、抓点、预抓取位姿、回撤路径均依赖当次场景。成功动作轨迹只作经验，不能直接重放到新设备或已变化的现场。 |
| 实时状态与控制权 | 关节位姿、夹爪接触、力矩、故障、使能/模式、相机占用、其他控制源、网络延迟、时间戳新鲜度每次重读。PID、socket、锁文件、运行中目标、旧请求/结果不复制到其他机器。 |
| 证据和当前任务范围 | 测试、抓取成功、精度残差和经验结论归属于当时的设备与条件；当前目标和授权服从本会话，不能从另一设备的历史记录补出。 |

## 参数的身份与保存

新配置、观测和派生模型至少能追溯到 `site_id`、目标机械臂/基座、相机角色与实际SDK序列号；同时记录采集设置、坐标系/单位、来源、时间/版本及验证范围。仅凭角色名 `front` 或 `left_wrist` 不足以匹配参数。

- 各服务器使用独立运行配置文件；各机械臂/相机的参数有独立身份。不存在跨服务器、跨臂、跨相机的参数默认继承或合并。
- 读取单帧RGBD时，使用该相机该次实际流的内参、畸变和深度比例；不要从另一份观测或历史分辨率推算。跨相机、跨主机时间戳不假设同步。
- 新设备尚缺的参数标为未知，继续做能完成的只读核验。只有依赖该参数的规划/动作等待核验；不能用旧设备参数补齐。
- 新标定写入本站独立、带版本/时间的文件，保留旧结果；未经用户明确要求不覆盖原参数文件。部署共用代码时只同步所需源码，排除站点运行配置、标定、证据、运行目录和认证资料；不直接覆盖整套项目配置。
- 同一实体同一安装的历史标定也要核对身份、采集模式和验证范围后再使用；实体/安装改变后旧数据仍保留作历史，不能改标签冒充新设备标定。

## 现有实现已知的适用假设

共用接口已在三个现场接入，以下后端假设仍不等于通用硬件支持：

- [protocol.py](../../../src/agilex_control/protocol.py) 固定六关节、Piper帧ID/故障位、模式帧及夹爪编码；它是经过本站验证的Piper后端，不是通用机械臂协议。
- [kinematics.py](../../../src/agilex_control/kinematics.py) 支持两个互斥参数源：原 `fk_file` 调用 SDK 的 `C_PiperForwardKinematics(1)`，或显式 `mdh_mm_rad` 六行 `[d毫米, a毫米, alpha弧度, theta_offset弧度]`。`.38` 用户确认是 Piper X，本站独立模型已对两臂反馈和抬升结果核验；不能再使用普通 Piper FK。当前一份配置的几何和关节限位仍用于其中两臂；若同一服务器两臂型号/参数不同，需按臂扩展，不能填同一组数值冒充支持。
- [can_bus.py](../../../src/agilex_control/can_bus.py) 假设配置里的每个执行臂有对应总线，使用固定反馈ID及Linux x86_64时间戳布局。主从臂共用总线或反馈有偏移时需先验证适配。
- [cameras.py](../../../src/agilex_control/cameras.py) 读取各相机实际流的内参与深度比例；现有后端请求同一相机的RGB/深度使用相同尺寸/帧率。不同RGB/深度模式、非RealSense传感器等需求要扩展采集后端，不能声称只改IP就支持。
- `.56` 旧配置的 `camera_resolution` 是该现场已有默认值；新现场应独立核实每台相机模式，不从该配置继承。现有 `.56` 配置和标定在本次改造中不修改。
- [sites.py](../../../src/agilex_control/sites.py) 只解析并显示档案，不验证物理设备、不连接硬件，也不替代动作前核对。

`.38` 两根 CAN 已由用户确认各接一只前方执行臂；Piper X 模型、关节控制和三路 RGBD 已核验，手眼/TCP 标定仍未完成。不同固件的使能、模式缓存和参数查询差异见 [初始化](initialization.md)。扩展步骤与接口兼容要求见 [extending.md](extending.md)。
